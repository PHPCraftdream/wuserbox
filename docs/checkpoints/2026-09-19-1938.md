## Decisions

- **`StripOwn` skips objects the sandbox owns outright**, rather than
  stripping their entries the way it does for everything else. Owning it is
  what the cap (owner.go) answers; a list a sweep just wrote whole is no
  longer purely inherited, and without this exception `StripOwn`'s own
  criterion matched it and undid the cap moments after it landed.
- **`grant.Revoke` calls `acl.TakeBack`, not `acl.Remove`.** `TakeBack`
  processes root and descendants as one whole write; `Remove` only ever
  touched the root, which is exactly why a direct revoke left descendants
  uncapped (P0-2's core finding).
- **The three self-owned-root synthetic revoke tests skip on this desk
  rather than fail.** Reclaiming a fully self-owned, self-revoked tree needs
  `SeRestorePrivilege`, which an administrator token holds (disabled) and an
  unelevated one does not; the tests try to enable it, and only fail if it
  is held but reclaiming still does not work. Their setup root is created
  with `os.MkdirTemp`, deliberately outside `t.TempDir()`'s own tracked
  area, so a skip does not also trigger a failing auto-cleanup.
- **The `narrowOwn` sequential-read duplication in `sweep.go` is not being
  fixed yet.** Diagnosed and explained to the user (proposed parallelizing
  the write/decide pass the way the read pass already is); the user has not
  asked for it, so nothing was changed there this session.
- **`wuserbox` is being installed as a system binary via `go install
  ./cmd/wuserbox`, reinstalled on request as `main` moves**, rather than
  built once and left stale; no version pinning or tagging is in place.
