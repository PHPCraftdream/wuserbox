The arc, in order. A first round on the profile copier: the mirroring's list

apart -- which mattered because the same fold was the record's ownership key,
and the record decides what `Clear` deletes. A third round closed a hole where
a `?` run wider than two could not cross the TxR index, so a glob spelling it
that way reached the hive unrefused. And a fourth, the release review, is the
one still open.

Two habits produced most of the value and both were learned the hard way here.
Measure the volume rather than the operating system: two tests were written
against this desk's uppercase table and turned red on a GitHub runner whose
table differs, and `fold.go` now says "per-volume is not a figure of speech"
because it cost a red build to learn. And do not let an approximate comparison
decide a deletion: the ownership question stopped folding at all and asks the
file system, through `os.SameFile` on handles opened inside the profile root.

The release review, verified rather than taken on trust, says P0 and P1 block.

## Decisions

- **The ownership comparison asks the volume, not a fold.** Both wrong
  directions of a fold delete: joining two places the volume holds apart makes
  the record claim files this tool never copied; holding one place's two
  spellings apart makes `forget` clear a copy the list still names. So
  `forget`'s keep and `copyEntries`' vouch open both spellings through the
  profile's `os.Root` and compare with `os.SameFile`. Everything else still
  folds, and `fold.go` now says which comparisons can afford to be wrong only
  by joining.
- **The fold is ToUpper, and it is the volume's answer rather than Unicode's.**
  Measured on this desk: ToLower agreed with the file system on three of seven
  pairs, ToUpper on six, and its one miss is on the side that spares a stray
  rather than taking a file. Which pairs a volume joins cannot be written down
  anywhere -- the table is built when the volume is formatted -- so the test
  asks the volume it runs on and says in its log where that left it with
  nothing to check.
- **OWNER RIGHTS goes only on objects the sandbox account owns.** Decided with
  the operator against two wider shapes. The operator's own files are not
  touched. The accepted residual, to be written into the code rather than
  discovered later: between two sweeps a sandbox can still re-permission a file
  it created itself.
- **The hive measurement asserts the defect on purpose.** Two of its
  assertions hold the current picture in place, so it goes red the day #209
  lands, and correcting the test, the investigation and `docs/limits.md` is
  part of that change rather than a follow-up.
- **`SECURITY.md` needs no work.** The review's P3-1 is wrong: it exists at
  `.github/SECURITY.md` and `.github/CONTRIBUTING.md` links to it relatively,
  so the link resolves. Verified.
