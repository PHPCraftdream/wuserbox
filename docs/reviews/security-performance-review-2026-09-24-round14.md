## P3-1 — отказ `Stat` у source читается как его отсутствие

**Evidence.** `copyEntries` после `os.Stat(src)` направляет **любой** `err != nil` в ветку «источник исчез или никогда не существовал» (`internal/policy/profile/copy.go:294–331`), не выделяя `os.IsNotExist`. При пустом previous record `vouches` отвечает absent и Copy продолжает без копии. `previewEntries` так же пропускает любой `Stat` error (`internal/policy/profile/preview.go:119–125`). Код зеркала уже различает отсутствие и прочий отказ у destination (`internal/policy/profile/mirror.go:234–245`).

**Impact.** Если существующий source временно не описывается из-за access/sharing/I/O error, Copy может успешно закончить и затем запустить программу без требуемого credential/config entry; Plan покажет его отсутствующим. При ранее записанной копии `vouches` обычно удержит record, поэтому этот путь сам по себе не показывает sandbox escape или потерю прежней записи. **Confidence:** высокая для control flow, средняя для частоты на реальных user profiles; отказ source локально не инжектировался. **Recommendation:** только `IsNotExist` трактовать как отсутствие, остальные ошибки возвращать из Copy и Plan; добавить адресный отказ source в tests.

## P3-2 — audit молча прекращает обход недоступной ветки

**Evidence.** `Audit` увеличивает `unreadable` при ошибке чтения permission list (`internal/cli/inspect/audit.go:64–69`), но при ошибке `os.ReadDir` просто возвращается из рекурсии (`:84–87`). Итог всё равно печатает число найденных и возвращает `nil` (`:94–102`); `fixedDrives` также игнорирует статус `GetLogicalDriveStringsW` (`:117–123`). Право прочитать security descriptor и право перечислить children — разные вопросы, поэтому успешный первый не подтверждает второй.

**Impact.** `--audit` может показать ноль или неполный список shared-writable каталогов без признака, что ветка не была проверена. Сам audit ничего не разрешает и ACL не меняет. **Confidence:** высокая для статического пути, средняя для конкретного числа пропущенных каталогов; refusal fixture не запускался. **Recommendation:** отмечать/возвращать ошибки перечисления и API drive list отдельно от permission-list errors; проверить fixture, где descriptor читается, а listing отказывает.

## Стоимость, проходы и allocations

Здесь `E` — число profile entries, `B` — children одного каталога, `M` — последовательные structural mutations, `D` — глубина, `N` — объекты ACL tree. В обычном полном snapshot один directory `ReadDir(-1)` создаёт `children`, `childAt`, `byName` за `O(B)` времени и Go-памяти (`place_resolver.go:336–372`). Первое alias resolution может пройти `B` children и открыть ещё не канонизированные; полный scan оставляет ответы в `byCanonical`. На проверенном сценарии 4/8 entries последовательные refresh не добавляют `M·B` посещений, а делают `O(M·D)` обходов цепочки и адресную переиндексацию изменённых recorded descendants (`place_index.go:263–312`). Это не универсальная гарантия `O(E+M)`: неполные scans, alias opens и вложенные изменённые поддеревья имеют дополнительную стоимость.

`canonicalNames` создаёт внутреннюю map при первом новом canonical path и держит её до конца resolver stretch (`place_resolve.go:141–160`, `place_index.go:97–103`). Новый test сравнивает allocations **первого** запроса после refresh с первым запросом fresh resolver, но не публикует абсолютные allocs/op и не профилирует whole Copy. File transfer использует один лениво выделенный 32 KiB Go scratch на pass (`internal/policy/profile/mirror_file.go:23–29`, `:139–142`). `pathid.Canonical` начинает с 256 UTF-16 slots, увеличивает буфер по ответу API и закрывает handle (`internal/win/pathid/pathid.go:83–115`); enumeration hard links закрывает native enumeration handle (`:223–279`). ACL sweep проходит `N` объектов с ограниченным окном workers, но pinned snapshot для sandbox-owned объектов и `WalkDir` listing всё ещё могут удерживать память пропорционально затронутому дереву/ширине каталога. Native heap profile и длительный handle-count эксперимент не выполнялись, поэтому полного отсутствия native leak этот обзор не утверждает.

Это существующие, отмеченные в round 13 пределы release evidence, а не новая регрессия трёх коммитов. Коммит этого отчёта не меняет проверенный production SHA.
